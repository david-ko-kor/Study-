발표 준비는 핵심 파일부터 보세요. 전체 목록에는 외부 엔진·사진·검사·이전 자료도 빠짐없이 포함했습니다.

데이터는 어디에 있을까?

localStorage는 브라우저의 보관함입니다.

이름표가 붙은 보관함에서 정보를 꺼내고 다시 넣습니다.
공용 데이터베이스나 다른 사람의 컴퓨터는 아닙니다.

상품 하나의 예시

{
  id: 101,                  // 상품을 찾는 번호
  ownerId: "student-a",     // 상품 주인의 계정 ID
  title: "수학 교재",       // 상품명
  price: 5000,              // 가격: 원 단위 정수
  zone: "본관 안심존"       // 희망 거래 장소
}

위 코드는 설명용 간단한 예시입니다. 실제 상품에는 사진·설명·판매 조건 등도 있습니다.

문장이 숫자가 되는 예

“카톡으로 와서 지금 바로 선입금하세요.”라는 한 절을 규칙으로 확인하면:

찾는 특징 값 이유
외부 연락 유도 1 ‘카톡’ 표현
결정·송금 재촉 1 ‘지금 바로’ 표현
선입금 요구 1 ‘선입금’ 표현

0은 해당 특징을 찾지 못했다는 뜻입니다. 여러 절에서 감지되면 2·3·4가 될 수 있습니다. 이 숫자 자체가 사기 여부의 정답은 아닙니다. “선입금하지 마세요”처럼 일부 예방 표현은 별도로 구분합니다.

조금 더 알아보기: 특징과 데이터 개수

문장 특징 12개와 가격 특징 5개로 채팅 학습 모델 입력은 17개입니다. 현재 문장 예측 호출은 가격 입력을 비워 두고, 가격 비교는 별도 모델로 실행합니다.

기본 가상 시나리오 60개 × 인사말 5종 × 상품 4종 × 가격 조건 9종 = 10,800행. 가격 전용 2,160행을 더해 12,960행입니다. 독립적인 실제 대화 12,960건이 아닙니다. 같은 원형 그룹을 분리해 학습 10,260행·평가 2,700행으로 나눴습니다.

채팅 모델은 나무 80개입니다. 합성 자료의 평가 결과는 실제 청소년 사기 탐지 정확도가 아닙니다. 모르는 표현·인용·반어법 등에서 틀릴 수 있습니다.

다른 두 기능과 혼동하지 마세요

가격 주의 모델

공식 새 제품 가격 8개에 가상 판매가를 조합해 152행을 만들었습니다. 가격 특징 5개와 별도 나무 80개를 사용합니다.

가격 배수 계산은 나눗셈입니다. 2.5배 이상 주의 라벨은 시연 가정이며 실제 사기 정답·중고 시세가 아닙니다.

학생증 OCR

Tesseract.js와 제공된 한국어 인식 자료를 사용합니다. 사진의 글자를 읽고 학교 목록·입력값과 맞춰 봅니다.

우리가 OCR 모델을 처음부터 학습한 것이 아니며 얼굴 대조·학생증 진위·실제 재학 여부는 확인하지 않습니다.

학생 앱 실행에는 Python·Node.js가 필요하지 않습니다. 앱은 브라우저에서 동작합니다. 모델 재학습과 자동 검사를 하는 개발 환경은 별도로 필요합니다.

30초 설명 틀

  2. 입력: 사용자가 무엇을 넣거나 누르나요?

예시 — “제품등록은 사진과 상품 정보를 올리는 기능입니다. product.html에서 입력하고 product.js에서 가격과 빈칸을 검사해 sm_items에 저장합니다. 메인에서는 app.js가 상품 카드를 그립니다. 같은 브라우저에서 사용하는 체험용이라 다른 기기와는 공유되지 않습니다.”

위 문장은 설명 예시입니다. 직접 한 요청·코드 수정·검사는 본인 활동에 맞게 말하세요.
